Activity 12 — teacher notes

Sending Messages by Radio. The server is removed, the whole room shares one channel, and the class hears what that costs as well as what it saves.

▶ Student page 📚 All teacher notes ← Activity 11 notes 📌 Pin reference
Keep this link to yourself. Unlisted and hidden from search engines, but the repository is public — anyone with the URL can read it.
This is the only activity in the module with no simulator. There is no Wokwi project and there cannot be one. If a student has no board today, pair them — there is no fallback route to give them.

What is being taught

  • One idea: the middle is gone. Activity 11 needed WiFi, an account, a key and a server in a data centre. Today none of them exists and the message still arrives. That sentence is the hero, the first section and the last quiz question.
  • The honest cost is taught alongside the win. No acknowledgement, no ordering, no address. The server was doing all three of those jobs, and the class should be able to name at least one of them by the end.
  • UART is the new hardware idea. Two chips, two wires, no addresses — deliberately contrasted with Activity 7’s I²C bus, which has several parts and an address each.
  • Mode pins are the thing that will eat the lesson if you let them. They idle at 1, 1, 1, which is asleep, and every failure mode is silent. Three lines at the top of every program.
  • Broadcast, and collisions. Twenty Shells filling with the same words at the same instant is the moment of the lesson. Do not rush past it to get to the code.
  • Reused, not re-taught: the loop, sleep, Pin, print() with commas, if, joining text with + and str(), def (Activity 11), and decode() (Activity 11).
  • Genuinely new syntax, and it is only two things: hexadecimal literals (0x) and picking one item out of six with a number in square brackets. Both appear only in the channel program, and both are explained on the student page.
  • No for loops, still, and no elif is needed.

The radio, and what it is not

  • The module is an Ebyte E70-433MT14S — a TI CC1310 using GFSK.
  • It is not LoRa. LoRa is a different, patented way of shaping the wave, made by Semtech (the E32, E22 and E220 modules). The two cannot hear each other, even on the same frequency. If anyone has older material calling this activity a LoRa activity, it is wrong and the student page deliberately never says the word.
  • Channel 23 is 433 MHz and channel 24 is 434 MHz — 410 plus the channel number. Those two sit inside the licence-free band; the other twenty-nine do not. That is the honest answer to the licensing question: no licence is needed for what the class is doing, and going outside those two channels is not a technical detail but somebody else’s allocation.
  • The channel change is permanent. Byte 0 is set to the save-for-good command, so it survives a power cut. See Putting a board back below.
  • AUX (GP21) is not used today. It is the busy line — high when the radio is free. Asking it instead of waiting a fixed time is the professional version of the two sleep calls in the channel program, and it is a good going-further conversation.

Antennas on, before anybody presses Run A module transmitting into nothing can damage itself. Walk the room once. It takes thirty seconds and it is the only hardware risk in the activity.

How to run the room

  • Board A stays on channel 23 running the sending program. That is the broadcast the class catches in Part 1.
  • Board B moves to channel 24, runs the listening program, and goes on the projector. Board B is the only proof the class gets that Part 3 worked — without it, thirty students send messages into a room and see nothing.
  • Run Part 1 as a whole-class moment. Everybody has the program loaded and running before you press Run on Board A. Twenty Shells filling at once is the lesson.
  • Between Parts 2 and 3, check every hand is up. Anyone still on channel 23 fails silently for the rest of the lesson and will not know why.
  • Delete the wait inside the if once, live, and let them watch half a message arrive. Then put it back.
  • Let the collisions happen in Part 3 rather than preventing them, then ask how a room of thirty people solves the same problem. Taking turns, and somebody saying who speaks next, are both real answers used by real radio systems.

The exercise answer — never leave it in the dark

Count the messages, and print the number in front of each one. Three changes to the listening program; nothing about the radio moves.

Accepting itWhat to look for
The counter lineAbove the loop, at no indentation. Inside the loop it resets every trip and the count never passes 1 — and that looks like a broken adding line.
The adding lineInside the if, at eight spaces. At four spaces it counts trips round the loop, not messages, and the number races away while the Shell stays quiet. This is the whole exercise.
The printing lineCommas, not +. print() joins a number to text on its own; + would need str() and is also accepted.
The acceptance testSend exactly five and count them landing. The last number must be 5.
Why this exercise It needs no new syntax at all — the student wrote the same counting line in Part 3 — and it puts the whole weight of the task on where a line goes rather than what it says. That is the same lesson as Activity 2’s indentation, arriving one last time.

Putting a board back on channel 23

Channel changes survive a power cut, so a board left on 24 will still be on 24 next term. In the channel program, change 24 to 23 and run it once. Everything else is handed back exactly as it was found, because only byte 4 is ever touched.

Code is shown as a picture — turn on JavaScript to see it.

Worth doing as a five-minute whole-class step at the end of the lesson rather than discovering it in the next one. If a board is ever left in an unknown state, run the channel program and read the before line — it reports what the radio actually thinks it is set to.

Before the lesson

  • Set up both of your boards and run the whole thing once. Board A sending on 23, Board B listening on 24. Not optional — there is no simulator to fall back on.
  • Check every antenna in the kit is screwed on, including the spares.
  • Know how many boards are in the room. One each is fine and is what the activity assumes: the instructor broadcasts, the class listens, then the class answers on a second channel. A pair per board also works, and halves the collisions in Part 3.
  • Put Board B on the projector before the lesson starts, running and visible. Part 3 is meaningless without it.
  • Decide whether the class ends on 24 or on 23, and budget five minutes if it is 23.
  • Have the three programs on your own machine so you can put a stuck student back on track without retyping.
  • Thonny preset to MicroPython (Raspberry Pi Pico); pin reference open on every machine.

Teaching notes

  • Open by unplugging the internet. Ask what Activity 11 needed. Write the list on the board — WiFi, account, key, server — then cross all four out and say the message still arrives. That is the whole activity in one minute.
  • The mode pins deserve five minutes on their own, before any code. They are three ordinary output pins doing something students have never seen a pin do: configuring another chip rather than driving something.
  • The silence in Part 1 is not dead time. Let it sit. A room of quiet Shells waiting for one transmitter is the difference between broadcast and everything they have done before.
  • Do not explain the six bytes exhaustively. The picture and the table are enough; the point is read–change–write, and that reading first is what keeps the other five safe.
  • Hexadecimal is worth one sentence, not a lesson. It is a way of writing a byte, and the student page says so. Anyone who wants more can ask.
  • The collision conversation is the best five minutes in the activity. Ask how a room of people takes turns, then say that every real radio system had to invent that, because the air does not do it for you.
  • Close the module here: from one LED on a pin to a message through the air with nothing in the middle. It is worth saying out loud.
