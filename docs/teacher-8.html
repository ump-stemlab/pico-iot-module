Activity 8 — teacher notes

Sensors and Numbers. One idea in two halves: a sensor measures, and a measurement is a decimal that has to be shortened and re-typed before a screen will take it.

Keep this link to yourself. Unlisted and hidden from search engines, but the repository is public — anyone with the URL can read it.

What is being taught

  • One idea, two halves. The sensor is the reason decimals appear; round() is the only thing that makes them fit. Same shape as Activity 7’s screen-and-library. Do not split them.
  • New hardware, no new pins. The accelerometer sits on the I²C bus built in Activity 7 — GP0 and GP1, address 0x68. Say this out loud: it is the payoff for the whole of last lesson.
  • The genuinely new syntax is one thing: str(). Everything else on the page is Activity 7 or earlier. round() is new but obvious; str() is new and surprising, and it is where the period will be lost.
  • The tail of digits is not an error. The sensor reports whole steps of 1/16384 g, so almost every reading is an untidy fraction and MicroPython shows about seven significant digits of it. Students will assume something is broken.
  • Round last, not first. Rounding discards. It belongs at the moment of display, never at the moment of reading.
  • A library may depend on another library. imu.py needs vector3d.py. That is the only new thing in today’s library step.
  • > is taught here now, in the body, and exercised in the exercise. The point to make out loud: a measurement is almost never exactly anything, so == 1.0 is the wrong question. > asks which side of a line the reading landed on, and that always has an answer.
  • The exercise brings an LED back for the first time since Activity 6, on GP11. Nothing about the sensor changes; the light is a second way of saying what the screen already says, for somebody not looking at the screen.
  • No elif and no for loops, still — elif arrives in Activity 9. Nothing here needs either.

The address, and the one thing to correct if a student reads ahead

  • The sensor is at 0x68, and no code sample on either page types an address — the library scans the bus and finds it. Keep it that way.
  • Activity 7 taught that a datasheet’s 0x78 is MicroPython’s 0x3C — the same address with the read/write bit tacked on. That is a real trap but it is not a universal rule. 0x68 here is already the 7-bit form and must not be halved; halving it gives 0x34, which is nothing. The student page says so explicitly.
  • Verified against the driver: imu.py looks for addresses 104 and 105 (0x68 and 0x69) and takes whichever answers. AD0 tied high would make it 0x69; on the LilEx5 it is not.

The main program — one tilt number, two ways

Code is shown as a picture — turn on JavaScript to see it.
  • The print is not decoration. It is the only place the class ever sees the untouched reading. Without it the whole decimals lesson is theory. Do not let anyone delete it as “tidying up”.
  • The long line is the lesson. Build it on the board from the inside out — reading, then rounded, then words — and count the three closing brackets together.
  • sleep(0.5) not 0.1: a number that changes five times a second is unreadable. Half a second is slow enough to read and fast enough to feel live.
  • The loop is back after Activity 7’s loop-free program. Nobody has ever noticed this, but if someone asks: a fixed message does not need repeating, a measurement does.
  • Verified in Wokwi during this build. This exact program runs on wokwi-mpu6050 and board-ssd1306 on one bus, with imu.py, vector3d.py and ssd1306.py pasted in as project files. Dragging the X slider to 1.15 g printed 1.149963 in the console and put 1.1 on the glass.

Exercise answer — a light that knows it has been tilted

Code is shown as a picture — turn on JavaScript to see it.
  • One new line above the loop and one if/else inside it. Everything else is the program they have just typed, untouched. If a student has rewritten the whole file, ask why.
  • >, not ==. This is the point of the exercise. A student who writes == 0.5 gets a light that essentially never comes on, and no error at all — let them watch it for thirty seconds before saying anything.
  • The question is asked of tilt, not of the rounded copy. Both work today. Say why the habit matters and move on — Activity 10 is where it starts to bite.
  • The else is load-bearing. Without it the light comes on once and stays on for ever, because nothing has been told to switch it back. The commonest wrong answer.
  • Accept any threshold from about 0.4 to 0.8, and accept any variable name for the LED. Accept the decision before or after the screen work.
  • Tilting the other way leaves it dark, because −0.9 is not more than 0.5. That is correct behaviour, it looks like a bug, and it is going-further task 1. Expect the question and enjoy it.
Wokwi pairs need an LED, a resistor and the sliders The exercise adds a part on the Wokwi route: LED long leg through a 330 Ω resistor to pin 15 (GP11), short leg to a ground. The wiring diagram is on the student page. And the sensor still needs clicking while the simulation runs to get its sliders.

Before the lesson

  • Put imu.py and vector3d.py on every real board yourself. Same argument as Activity 7, doubled — it is two files now, and it is not what the lesson is about.
  • Both files from ump-stemlab/stemcube on a shared drive or a USB stick. Assume the lab has no internet.
  • Run the tilt program on each board once. A dead accelerometer and a missing str() do not look alike, but a board whose sensor never answers wastes ten minutes.
  • Wokwi route: rehearse clicking the sensor to get its sliders. It is the single step that makes the simulator route work today, and it is not obvious.
  • Activity 7 done, and ssd1306.py still on every Pico. Today needs the screen working before anything else can be seen.
  • Thonny preset to MicroPython (Raspberry Pi Pico); pin reference open on every machine.
  • Desk space. Students will be picking boards up and turning them over with cables attached.

Teaching notes

  • Open by tilting a board that already works. Numbers moving on a screen because somebody moved their hand is the hook, and it takes ten seconds.
  • Put the raw number on the projector and let them react to it. Somebody will say it is broken. That question is the whole first half of the lesson and it is better asked by them than announced by you.
  • The reading widget on the student page is worth five minutes. Drag, switch to 0 places, drag again, then turn the words step off and press send. Three lessons, nothing to type.
  • Do the number-versus-words distinction with paper. Write 0.9 on one card and the three characters 0, ., 9 on three cards. Ask which one you could cut in half. It lands in fifteen seconds and it sticks.
  • Draw the line on the whiteboard before they start the exercise. A number line from 0 to 1, a mark at 0.5, and five dots where real readings landed. Ask which of the dots is exactly 1. Nobody forgets after that.
  • Say “no new pins” out loud and point at the pin table. Activity 7 was expensive; this is where it pays — and note that the exercise’s LED is an old pin, not a new one.
  • The two library files are on the Pico for good. Activity 10 uses them again without any of this.
  • Safety rules unchanged: never 5V to a GP pin, never a power pin to GND, power off at SW5 before changing wires.
