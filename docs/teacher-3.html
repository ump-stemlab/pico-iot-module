Activity 3 — teacher notes

Digital Input. One idea in two halves: a pin can be read, and a program can talk back.

▶ Student page 📚 All teacher notes ← Activity 2 notes 📌 Pin reference
Keep this link to yourself. Unlisted and hidden from search engines, but the repository is public — anyone with the URL can read it.

What is being taught

  • One idea, two halves that need each other: a pin can be read, and a program can say what it saw. A value you cannot see is invisible; a message with nothing to say is a party trick.
  • The inversion is the lesson. A button reads 1 untouched and 0 when pressed — backwards from every student’s intuition. This is Activity 3’s equivalent of Activity 2’s indentation, and it bites again in Activity 4. Budget time for the two pull-up diagrams.
  • The Serial Monitor / Shell gets its own section. First activity whose answer is on the screen rather than the board — a student looking at the wrong panel is the biggest source of “mine isn’t working”.
  • sleep returns for a different reason: throttling the console, not slowing a blink. Say it is a callback; do not re-teach it.
The two questions to open with “The Pico has done everything you told it for two whole activities. How would it ever know you were in the room?” Then: “and how would it tell you what it saw?”
No if in this activity, on purpose Press-the-button-light-the-LED needs if, and that is the whole of Activity 4. The mission here is deliberately watch the number change. Expect a student to ask for the LED version; the answer is “yes, and that is exactly what we do next lesson.” Do not let it be smuggled in disguised as inverting the value or feeding it straight to an LED — both work, both skip the idea, and both make Activity 4 land flat.

The main program

Six working lines; comments optional as always.

The same setup line works on both routes One line with PULL_UP, for Wokwi and the LilEx5 alike. In Wokwi the pull-up does all the work — take it out there and the pin floats, which is worth demonstrating once. On the board the buttons already idle high, so the line behaves identically and students never hold two versions in their heads. If asked whether the board “needs” it: writing it costs nothing and guarantees the pin is never left floating.

Exercise answer — two buttons on one line

Code is shown as a picture — turn on JavaScript to see it.

Needs one thing from Activity 1 (each part gets its own name) and two from this one (a second input pin, and a print carrying more than one thing). The commas are the only new syntax and they are taught in Clue 2. Insist on three things:

  • One line, not two. Two print lines per loop works, but the columns stop lining up and the point — telling them apart at a glance — is lost.
  • Two names. Reusing one name is the Activity 1 mistake resurfacing; the symptom is that only one button appears to work.
  • Labels in quote marks. Without them Python hunts for a variable and reports NameError — the clearest demonstration in the module of what quotes are for.
Wokwi needs a second pushbutton One leg to GP3, the diagonally opposite leg to any GND. This is where the four-leg trap catches the students who got away with it the first time by luck.

Going-further answers

TaskAnswer / what to say
Add SW3 on 4A third name and two more commas. Nothing new — which is the point: the pattern scales.
Read the slide switch SW4 on 15Read exactly the same way, but the value stays instead of springing back. Momentary versus latching — worth naming out loud. The code cannot tell them apart; only the hardware knows.
Wait two seconds insteadMost taps are missed. Cheap, excellent demonstration that the program takes snapshots rather than watching continuously.
Wait 0.01A hundred lines a second; the panel becomes unusable. Same lesson as the “no wait at all” preset.
Print a sentenceAny label they like — watch for missing quote marks. First time output has been designed for a human reader.
Leave the pull-up outWokwi only. The pin floats and the numbers wander. On the real board the effect is muted because the board holds the line — itself worth pointing out. Do not encourage poking at wires on a powered board.

Before the lesson

  • Activities 1 and 2 done. Loops, indentation, sleep, stopping a loop and naming a pin are all assumed.
  • A board and USB cable per pair, and check SW1 actually clicks on each. A dead button is very hard to tell from a wrong program.
  • Thonny installed, interpreter preset to MicroPython (Raspberry Pi Pico).
  • Make sure the Shell panel is visible on every machine (Thonny: under View). If it is closed, nothing this activity produces appears anywhere.
  • In Wokwi, drag the Serial Monitor taller on the projector copy.
  • A pushbutton diagram to hand — the four-leg problem arrives within ten minutes and is much easier to point at than to describe.
  • The pin reference open on every machine.

The mistakes students actually make

Teaching notes

  • Teach the panel before the program. Have everyone find the Serial Monitor or Shell and print one word before any button work. Two minutes, and it removes the biggest source of “mine isn’t working”.
  • The inversion deserves a physical demonstration. Hold a finger over the button without touching, ask what the pin reads, then press. Ask what the finger removed. “Pressing pulls the pin down” is the sentence you want back.
  • The button widget is worth three minutes on the projector. Run it, hold the button, then press No wait at all and hold again — the number still changes but the output is useless.
  • A loose tactile switch and a multimeter is the best prop in the module. Buzz out the pairs in front of the class; nothing on a screen beats hearing the beep with the button untouched.
  • Two sets of brackets, one inside the other, is the first nested expression here. Read it from the inside out, out loud, twice.
  • Resist letting the class jump to lighting an LED with the button. That is Activity 4, and it lands much better if they arrive wanting it.
  • Safety rules unchanged: never 5V to a GP pin, never a power pin to GND, power off at SW5 before changing wires.
