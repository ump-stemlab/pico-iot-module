Digital Input. Everything on this page is for the person running the lesson.

Keep this link to yourself. The page is unlisted and hidden from search engines, but the repository is public — anyone given the URL can read it. Share it with staff, not in the student handout.

What is actually being taught

One idea, in two halves that need each other: a pin can be read, and a program can talk back to you. Neither is worth much alone. A value you cannot see is invisible; a message with nothing to say is a party trick.

The reading is easy. The inversion is the lesson. A button reads 1 when nobody is touching it and 0 when they are, and that is backwards from every student's intuition. It is this activity's equivalent of Activity 2's indentation: the thing they will get wrong, and the thing that will bite them again in Activity 4 when the wrong comparison makes an LED come on at exactly the wrong moment. Budget time for the two pull-up diagrams and do not rush them.

The question to ask before they type anything “The Pico has done everything you told it for two whole activities. How would it ever know you were in the room?” Let them get to “it would have to look at something”, and then ask the second question: “and how would it tell you what it saw?” That is the whole activity, in two questions.
There is no if in this activity, on purpose The obvious mission — press the button, light the LED — is impossible without if, and if is the whole of Activity 4. The mission here is deliberately watch the number change. Expect a student to ask for the LED version; the right answer is “yes, and that is exactly what we do next lesson.” Do not hand them if, and do not let a keen student smuggle it in disguised as inverting the value or feeding it straight into an LED — both work, both skip the idea, and both make Activity 4 land flat.

The main program

Code is shown as a picture — turn on JavaScript to see it.

Six working lines. The comments are optional, as always — do not mark a student down for a program that has none.

The same line works on both routes The student page teaches one setup line, with PULL_UP, for Wokwi and for the LilEx5 alike. In Wokwi the pull-up is doing all the work — take it out there and the pin floats and the numbers go to nonsense, which is worth demonstrating once. On the board the buttons already idle high, so the line behaves identically and students never have to hold two versions of it in their heads. If a student asks whether the board “needs” it, the honest answer is that writing it costs nothing and guarantees the pin is never left floating.

Exercise answer — two buttons on one line

Code is shown as a picture — turn on JavaScript to see it.

The exercise needs one thing from Activity 1 (each part gets its own name) and two from this one (a second input pin, and a print line carrying more than one thing). The commas in print are the only genuinely new syntax, and they are taught in Clue 2.

Accept any sensible names and any sensible labels. Three things worth insisting on:

  • One line, not two. Two separate print lines per loop is the common answer and it works, but the two columns no longer line up and the point of the exercise — telling them apart at a glance — is lost. Ask them to watch their own output while pressing a button and decide which is easier to read.
  • Two names. Reusing one name for both pins is the Activity 1 mistake resurfacing. The symptom is that only one button ever appears to work.
  • Labels in quote marks. Without the quotes Python looks for a variable with that name and reports a NameError, which is a useful accident — it is the clearest demonstration in the module of what quote marks are for.
If a pair finishes very early Ask them to make the two columns line up neatly even when a number changes width. They cannot, yet — every value here is a single digit, so it always does. Then ask what would happen if one of them printed 10. It pre-teaches formatting, which comes back in Activity 7 with decimals.
Wokwi needs a second pushbutton Wired the same way: one leg to GP3, the diagonally opposite leg to any GND. This is where the four-leg trap catches the students who got away with it the first time by luck.

Going-further answers

TaskWhat happens / what to say
Add SW3 on 4A third name and two more commas. Nothing new — which is the point: the pattern scales.
Read the slide switch SW4 on 15It reads exactly the same way, but the value stays where you put it instead of springing back. This is the difference between a momentary and a latching switch, and it is worth naming out loud. It also makes the point that the code cannot tell the two apart — only the hardware knows.
Wait two seconds insteadMost taps are missed entirely. Excellent, cheap demonstration that the program is not watching continuously — it is taking snapshots. Leads naturally to the idea of catching an event rather than sampling a state, which this module does not cover but good students will ask about.
Wait 0.01A hundred lines a second. The panel becomes unusable and pressing the button makes no visible difference. Same lesson as the “no wait at all” preset on the student page.
Print a sentenceAny label they like. Watch for missing quote marks. A nice one to show on the projector — it is the first time output has been designed for a human reader.
Leave the pull-up outWokwi only — do this one in the simulator. The pin floats and the numbers wander. On the real board the result is less dramatic because the board's own hardware holds the line, which is itself a useful thing to point out. Do not encourage poking at wires on a powered board.

Before the lesson

  • Activities 1 and 2 must be done. Loops, indentation, sleep, stopping a forever-loop and naming a pin are all assumed and none of them is re-taught.
  • A LilEx5 board and USB cable per pair; check that SW1 actually clicks on each board before the lesson. A dead button is very hard to distinguish from a wrong program.
  • Thonny installed, interpreter preset to MicroPython (Raspberry Pi Pico).
  • Make sure the Shell panel is visible on every machine. If a student has accidentally closed it, nothing this activity produces will appear anywhere and they will conclude their program is broken. It is under View in Thonny.
  • In Wokwi, drag the Serial Monitor taller on the projector copy so the class can see more than two lines of it.
  • Have a spare pushbutton diagram to hand — the four-leg problem will come up within ten minutes and it is much easier to point at than describe.
  • The pin reference open on every machine.

The mistakes students actually make

What they didWhat they seeWhat to say
Assumed pressed means 1Nothing visibly wrong — they simply describe their own output backwardsThe big one. It does no damage today and enormous damage in Activity 4. Make every student say out loud, while pressing, “my finger is down and the number is zero.”
Two legs of the button on the same bar (Wokwi)A steady column of 1s that never changesThe four-leg trap. Ask them to trace which two legs are already joined. Move one wire to the diagonally opposite leg.
Looking at the wrong panel“It's not doing anything”Very common, because no previous activity produced any text at all. Point at the Serial Monitor or Shell before you look at their code.
No PULL_UPNumbers that flicker between 0 and 1 at random Beautiful failure, worth demonstrating on purpose in Wokwi. The pin is floating.
Pin.OUT left in from Activity 2A steady column of 0s, or 1s, that never changesThey copied their old setup line and changed only the number. The word OUT is the one that has to change.
Missing brackets after valueSomething long and cryptic printed repeatedly, not a numberThey printed the question instead of the answer. The empty brackets are what actually asks it.
No wait, or the wait left outside the loopThousands of lines; the panel is unreadableBoth produce the same symptom. Check the indentation before assuming the line is missing.
Nothing indented under the loop lineIndentationErrorSame as Activity 2. The message names the line.
Wrong pin numberA column that never changesButtons are 2, 3, 4. LEDs are 11, 12, 13. There is no pattern — send them to the pin reference.
Knocked SW5The whole board goes deadThe power switch sits in the same numbering as the buttons. Expect this at least once per class.
Tapped too fast to be caughtAn occasional press that produces no 0Not a bug. The program looks five times a second. Hold it down for a full second.

Teaching notes

  • Teach the panel before you teach the program. Have the class find the Serial Monitor or the Shell and print one word — anything — before any button work starts. It takes two minutes and removes the single biggest source of “mine isn't working”.
  • The inversion deserves a physical demonstration. Hold a finger over the button without touching it and ask what the pin reads. Then press. Ask them to explain what the finger removed rather than what it added. “Pressing pulls the pin down” is the sentence you want back.
  • The button widget on the student page is worth three minutes of class time. Put it on the projector, run it, and hold the button. Then press No wait at all and hold it again — the number still changes, but the output is useless. That single demonstration explains the sleep better than any sentence.
  • The four-leg button is the best physical prop in the whole module. If you have a loose tactile switch and a multimeter, buzz out the pairs in front of the class. Nothing on a screen beats hearing the beep with the button untouched.
  • Two sets of brackets, one inside the other, is the first nested expression in this module. “Ask the question, then show the answer” — read it from the inside out, out loud, twice.
  • print arrives here rather than in Activity 1 or 2 on purpose. Both of those had a light to look at; a console message would have competed with it. Here it is the only way to see anything, so it earns its place. If a student has been sneaking it into earlier work, praise them.
  • Resist letting the class jump ahead to lighting an LED with the button. See the warning at the top of this page — that is Activity 4, and it lands much better if they arrive at it wanting it.
  • The safety rules still apply: never join 5V to a GP pin, never join a power pin to GND, switch off at SW5 before changing wires.
