The activities

#ActivityThe one ideaNotes
0Getting Started The board, the simulator and Thonny. No electronics and no board needed — the point is that everybody can run something before Activity 1. teacher-0
1Light Up an LED A pin makes a light come on — variables, comments, GPIO numbers. No print(). teacher-1
2Make an LED Blink Loops, sleep, and indentation. Stopping a forever-loop is taught here and assumed after. teacher-2
3Digital Output & Servo PWM repurposed for movement: three duty values move a servo arm to left, middle, and right. The pin trap (GP28 = GPIO18 = header pin 12) and VBUS for power. print() arrives here for the first time. teacher-3
4Digital Input A pin can be read, and a program can print. The button reads 0 when pressed — the inversion everything later depends on. teacher-4
5Making Decisions if, then else. One equals puts, two equals asks. Two independent decisions in the exercise. teacher-5
6And, Or, Not Joining two whole questions into one. Each half must stand on its own. teacher-6
7Words on a Screen The OLED screen and the first library that is not built in — they need each other. Also the I²C bus: two wires, eight parts, one address each. teacher-7
8Sensors and Numbers A sensor measures rather than answers yes or no, so the number has a decimal point — and round() plus str() are what make it fit on a screen. No new pins: it joins the Activity 7 bus. teacher-8
9Soil Moisture The first analogue pin: a voltage on a wire, read straight off GP26 with no bus and no library. Two more things arrive with it — elif, because three zones is the first honest reason for it, and // for the percentage. The real lesson is calibration: the numbers mean nothing until the class has measured both ends themselves. teacher-9
10Internet and Data The reading leaves the room. Two halves: joining a WiFi network, and handing the message to a broker over MQTT. Still no new pins — the weather sensor is the third part on the Activity 7 bus. First activity that needs the Pico W, and the first that can fail for reasons outside the program. teacher-10
11Control from Anywhere The arrow turns round: the board subscribes instead of publishing. Three parts that only work together — subscribing, the first def, and check_msg() in the loop. Written self-contained, so it teaches WiFi, MQTT and the Adafruit IO account from scratch while 8, 9 and 10 are unbuilt. Needs the Pico W. teacher-11
12Sending Messages by Radio The middle is gone: no WiFi, no account, no server, and the message still arrives. UART (two chips, two wires, no addresses), the three mode pins — which idle at 1, 1, 1, meaning asleep, and whose every failure is silent — and channels. The honest cost is taught with the win: no acknowledgement, no ordering, no address. The only activity with no simulator. teacher-12
13Your Own Live Dashboard The middle is yours: the class deploys a Google Apps Script, posts every reading to it over HTTP as named values (JSON), and keeps the rows in a spreadsheet of its own — which is the first time the module has history rather than a live gauge. Posting is contrasted with Activity 10’s publishing: today the board waits for an answer. Ships finished code — the one exception to the typing rule. Both routes do the whole activity: Wokwi's Pico W reaches the real internet, and posts three readings where the LilEx5 posts twelve. teacher-13

Each activity adds exactly one idea and re-teaches nothing. If a class is struggling, the fix is almost always in the previous activity rather than the current one.

How the module is meant to run

Wokwi first, then the board

On the LilEx5 the wiring is inside the PCB, so the simulator is the only place students see a circuit. Both routes are on every page as tabs.

Code cannot be copied

Every program is drawn as a picture and the clipboard is guarded. Students type, or they learn nothing. This is deliberate — do not paste code into a chat for them.

No elif before Activity 9

Kept out of Activities 1–8 so the two-road picture of a decision survives. It arrives in Activity 9, where three zones is the first honest reason for it, and is fair game after that.

Libraries may be pasted

The no-copying rule is about students’ own programs. From Activity 7 a library file is pasted or copied onto the Pico — nobody retypes one. Say so, or the rule looks arbitrary.

No for loops until Activity 9

Every main program uses while True: only. Exercises follow the same rule — if a student reaches for a for loop, ask them to rewrite it without one. Activity 9’s elif arrives first; for loops are never explicitly introduced in this module.

Answers live here, not there

Student pages carry the task, the expected result and progressive clues. The worked answer is on these pages only.

Three safety rules, every lesson Never connect a 5V pin to a GP pin — GP pins are 3.3 V only. Never join a power pin to GND. Switch the board off at SW5 before changing wires.

Activity 13 adds no pins at all — it reuses the sensor bus, the screen and the WiFi radio. Activity 12 adds six pins — the whole radio block, and the last block of the board to be used. Activities 8, 10 and 11 add no pins at all — the tilt sensor and the weather sensor both joined the bus, and the Pico W’s WiFi radio is inside the chip rather than on a pin. Activity 9 adds GP26, the module’s first analogue pin and its first wire to the 40-pin header; only GP26, GP27 and GP28 can measure a voltage, and the H3 connector’s analogue inputs are not these — they come back over I²C. SW5 is the power switch and is not on a GP pin. GP0 and GP1 are the bus — shared by the screen and all eight I²C sensors, so nothing else may ever be wired to them. Full map: pin reference.

Kit check, once a term

  • Every board: SW1, SW2 and SW3 click; LED1, LED2 and LED3 light; the buzzer sounds; the OLED screen shows something when the Activity 7 hello program is run on it; the accelerometer answers when the Activity 8 tilt program is run on it.
  • ssd1306.py, imu.py and vector3d.py already on every real Pico, and on a shared drive or USB stick for the Wokwi route — see the Activity 7 notes and the Activity 8 notes.
  • Thonny installed, interpreter preset to MicroPython (Raspberry Pi Pico).
  • One USB cable per board that carries data, not only power.
  • Soil probes: test every one on a known cup before the lesson — a corroded probe reads exactly like a wiring fault. Store them rinsed and dry, never standing in wet soil, with their calibration numbers on a sticky note. Three female-to-female jumpers per probe, and a cup of soil per pair. See the Activity 9 notes.
  • Wokwi reachable from the school network, and the pin reference bookmarked on every machine.
