Activity 7 — teacher notes

Words on a Screen. One idea in two halves: the OLED, and the first library that is not built in.

What is being taught

  • One idea, two halves. The screen and the library need each other: the screen is the reason to add a library, the library is the only way to use the screen. Same shape as Activity 4’s read-and-print. Do not split them.
  • First new hardware since Activity 4, and the first part ever that sits on a bus rather than on a pin of its own. SDA is GP0, SCL is GP1.
  • Write, then show. Words go onto a page in memory; show() puts the page on the glass. This is the single biggest source of “mine isn’t working” today, because a missing show() produces no error at all.
  • Where a file lives is now a thing students have to think about. Up to today the only file that mattered was their own. The library has to be on the Pico’s disk, not the computer’s.
  • The two routes genuinely differ here, for the first time in the module. Wokwi: add a second project file. Thonny: save a real file onto the board. Say so out loud — students comparing notes across routes will otherwise think one of them is wrong.
  • No elif and no for loops, still. The exercise needs neither.

The address — what to say when a student finds 0x78

  • The driver’s default is 0x3C and the student page never asks anyone to type an address. Keep it that way unless a board misbehaves.
  • Datasheets and this board’s own documentation print 0x78. That is the same address with the read/write bit already tacked on the end: 0x3C shifted left by one. Both are “right”; MicroPython wants the 7-bit form.
  • Wokwi agrees: its SSD1306 OLED display part carries i2cAddress: 0x3c as its own default attribute.
  • If a board ever needs the other one, the alternative is 0x3D (0x7A in the shifted form), set by a solder link on the module. Run the scan below before believing it.

The main program — hello on the glass

Code is shown as a picture — turn on JavaScript to see it.
  • Eight working lines, and no loop — the first program since Activity 1 that ends by itself. Worth naming: the words stay because the screen holds what it was last given.
  • fill(0) is not strictly needed on a freshly made screen (the driver clears it), but it is in the program on purpose, because the exercise cannot work without it.
  • Delete the show() on the projector and run it. Thirty seconds, and it inoculates the class against the day’s worst bug.
  • Have them change "Hello" to their own name before moving on. It is the moment the board stops being a demo.

Exercise answer — SW1 and SW2 as words

Code is shown as a picture — turn on JavaScript to see it.
  • The order inside the loop is the lesson: wipe, write, show, wait. Any other order fails in a way that is worth looking at.
  • 48 is six letters’ clearance (6 × 8). Accept anything from 32 upwards that does not collide with the label.
  • Two independent if/else pairs, both at four spaces — Activity 5’s exercise shape, reused deliberately. A second if at eight spaces is still the most instructive wrong answer.
  • Accept any sensible words for the two states, and any sensible names.
  • sleep(0.1) is not compulsory. Without it the screen is redrawn hundreds of times a second and looks identical; with it the class can see the loop is a loop.
Wokwi pairs need two pushbuttons added Diagonally opposite legs, no resistor, GP2 and GP3 — Activity 4’s rule, unchanged. That is four more wires on top of the screen’s four. Real-board pairs have nothing to wire and will finish first; have the going-further list ready.

Before the lesson

  • Get the library onto every real board yourself, beforehand, if you can. Thirty students each copying a file is thirty chances to put it in the wrong place, and it is not what the lesson is about. Ten minutes with a USB hub saves the first half of the period.
  • If they must do it themselves, do it together, on the projector, before anyone writes a line of the program.
  • ssd1306.py from ump-stemlab/stemcube on a shared drive or a USB stick — assume the lab has no internet.
  • Check every screen lights. A dead screen and a missing show() look exactly the same. Run the hello program on each board once.
  • Wokwi route: nothing to install, but they need to be able to reach the library file to paste it. Have it open in a tab, or on the shared drive.
  • Activities 1–6 done. if/else and the button inversion are both needed for the exercise.
  • Thonny preset to MicroPython (Raspberry Pi Pico); pin reference open on every machine.

Teaching notes

  • Open with the screen, not the library. Show a board with words on it first. The library is a chore; it needs a reason to exist before anyone will care about it.
  • The page-and-glass widget on the student page is worth five minutes on the projector. Write both lines, then wipe, then show. Nothing to type, and it makes show() unforgettable.
  • Do the bus with people. Call a name across the room, then a message. Everyone hears both; one person answers. That is I²C, and it takes ninety seconds.
  • Hexadecimal needs one sentence and no more: it is a way of writing numbers, 0x3C is 60, nobody converts them by hand.
  • Let them paste the library. The no-copying rule is about their own programs. Say that out loud, or the rule looks arbitrary.
  • The library file is on the Pico for good. Activity 8 will use it again without any of this.
  • Safety rules unchanged: never 5V to a GP pin, never a power pin to GND, power off at SW5 before changing wires.
