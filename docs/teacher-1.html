Activity 1 — teacher notes

Light Up an LED. One idea: a name points at a pin, and a pin makes a light come on.

▶ Student page 📚 All teacher notes 📌 Pin reference
Keep this link to yourself. Unlisted and hidden from search engines, but the repository is public — anyone with the URL can read it.

What is being taught

  • One idea: a nickname points at a pin, and switching that pin on lights something. Variables, comments and GP numbers all arrive in service of it.
  • No print(), on purpose. The mission is a light, and a console message competes with it. print() arrives in Activity 3. If a student adds one, praise it and move on.
  • Do not skip Wokwi. On the LilEx5 the LED wiring is inside the PCB, so students never see a circuit unless they build one. That step is where the electronics is taught.
  • The light stays on for ever, and nothing turns it off. Ask “what would make it stop?” — that is Activity 2.

Exercise answer — all three LEDs

Code is shown as a picture — turn on JavaScript to see it.
  • The point is the second clue: one nickname can only point at one pin. Students who reuse led three times light only the green LED. Let them hit that before you rescue them — it is where variables stop being decoration.
  • Accept any sensible names. Push back only on names that lie, such as calling GP13 red.
  • Order does not matter. Name-then-switch-on per LED is equally correct and worth showing.

Going-further answers

TaskAnswer / what to say
Only red and greenDelete the yellow lines, or just its .on(). Ask which is tidier.
Name all three ledOnly green lights: each new led = Pin(...) overwrites the nickname, and the first two pins were never switched on. The most useful misconception in the activity.
red.off() at the endRed appears never to light — it does, for a few thousandths of a second. Sets up sleep in Activity 2.
Pin(14, Pin.OUT)The buzzer sounds continuously. Demonstrate once from the front rather than letting thirty pairs find it together.

Before the lesson

  • A board and USB cable per pair; check SW5 (power) on each.
  • Thonny installed, interpreter preset to MicroPython (Raspberry Pi Pico).
  • The Wokwi project up on the projector.
  • The pin reference open on every machine — needed from here on.
  • Decide the route. Most classes do Wokwi first and boards in the second half.

The pin numbers students get wrong

PartPinIf they miss it
LED1 red11—
LED2 yellow12Wrong colour lights, no error
LED3 green13Wrong colour lights, no error
Buzzer BZ114Loud continuous tone

12 versus 13 is the quiet mistake: nothing errors, the wrong colour simply lights. Say it plainly — a program that runs without an error is not the same as a program that does what you meant.

Teaching notes

  • The most common typo is lowercase pin. MicroPython is case-sensitive; the type-it-here box on the student page catches exactly this.
  • led is not a keyword. Renaming it to lamp throughout is a 30-second demonstration that variables are nicknames — and it pre-teaches the exercise.
  • Comments are new here. Students think # lines do something. Delete every comment, re-run, identical behaviour — then ask why anyone bothers.
  • The buzzer mistake is the best one in the activity: loud, obvious, and it makes the “code must match the copper” point better than any explanation.
  • Safety rules from day one: never 5V to a GP pin, never a power pin to GND, power off at SW5 before changing wires.
