Activity 2 — teacher notes

Make an LED Blink. One idea: a block of code can repeat.

▶ Student page 📚 All teacher notes ← Activity 1 notes 📌 Pin reference
Keep this link to yourself. Unlisted and hidden from search engines, but the repository is public — anyone with the URL can read it.

What is being taught

  • One idea: a block of code can repeat. The loop, the pause and the four spaces are all machinery in service of it.
  • Indentation is the lesson, not the blink. It is the first time whitespace changes meaning, and most of the class will get it wrong at least once. Do not rush the two comparison diagrams.
  • Stopping a forever-loop is taught here and assumed from now on. Every activity after this one runs in a loop.
  • Still no print(). A blinking light is its own output; it arrives in Activity 4.
The question to open with “In Activity 1 your light stayed on. What would it take to make it go off again?” Let them answer, then ask why adding an off at the end of Activity 1’s program does not appear to work. That is the whole activity, in one question.

Six working lines; the comments are optional. Do not mark a student down for a program without them.

Exercise answer — the traffic light

Code is shown as a picture — turn on JavaScript to see it.

Three groups of three inside one loop. It needs one thing from Activity 1 (each LED gets its own name) and two from this one (the loop, and an unequal delay). Accept any sensible order and names; insist on three things:

  • Every colour is switched off again before the next comes on. Students who only switch on end up with all three lit — an obvious, useful failure.
  • All nine lines indented. One group left at the left edge is the classic mistake, and the symptom is subtle: that colour appears to be skipped.
  • The yellow really is shorter. Three equal delays means they have not read the task.

Praise blank lines between the groups out loud — first formatting for a human reader since comments.

If a pair finishes very early Ask them to make the sequence twice as fast by editing one line only. They cannot — unless they invent a variable for the delay, which is going-further task 3 and an elegant answer for a beginner.

Going-further answers

TaskAnswer / what to say
Yellow blinks three timesSix more lines inside the loop. Someone will ask for a shorter way — there is one (for) and it is not in this module. Tell them the instinct is right and counted loops are the next thing they would learn.
Red and yellow togetherTwo on lines with no off between, a wait, then two off lines. Proves a pin holds its state until something changes it.
Name the delayA nickname set to 4 above the loop, used instead of the number. One edit changes the whole light. Best of the five — show it to the class.
A waiting time of 0No error. That colour flashes for microseconds and looks like it never came on. Same lesson as the too-fast preset.
Buzzer on 14A short beep every cycle. Loud — demonstrate from the front. Also a reminder that the buzzer is switched exactly like an LED.

Before the lesson

  • Activity 1 done. Wiring, pin numbers and variables are not re-taught.
  • A board and USB cable per pair; check SW5 on each.
  • Thonny installed, interpreter preset to MicroPython (Raspberry Pi Pico).
  • Wokwi on the projector. If the class saved Activity 1 projects, remind them to reopen rather than rebuild.
  • Know where the Stop button is in both tools. You will be asked within five minutes, by everyone, at once.
  • The pin reference open on every machine.

Teaching notes

  • Teach stopping before starting. Show the Stop button and Ctrl+C before anyone runs a forever-loop.
  • The blink widget is worth two minutes on the projector. Put the “too fast” preset up and ask what the LED is doing. Nearly everyone says “it is on”. It is blinking fifty times a second.
  • Indentation deserves a physical demonstration. Drag one line left on the board and ask what changes. Do not accept “it breaks” — make them say which lines now repeat.
  • while True is not explained as boolean logic here, on purpose. “True means keep going” is enough; True and False get their proper treatment in Activities 5 and 6.
  • The module borrows single tools (from time import sleep) so every activity’s import lines look alike. The other style is shown once, in a details block.
  • Encourage fiddling with the waiting numbers. Nothing can break, and the link between a number in a file and a thing happening in the world is the point of the course.
  • Safety rules unchanged: never 5V to a GP pin, never a power pin to GND, power off at SW5 before changing wires.
