🎯 Your mission

Tell a computer chip exactly what to do — and watch it obey.

Your LilEx5 board has a Raspberry Pi Pico on it. The Pico has pins, and each pin has a number. If you send power out of the right pin, a light comes on. That is the whole idea, and everything else in this module is built on top of it.

What you will learn

What a GPIO pin is

And why every pin has a number you must get right.

How to send power out

Setting a pin to output and switching it on.

How to type, save and run

Using Thonny, or the Wokwi simulator in a browser.

That code must match copper

The wrong number does the wrong thing — loudly.

💡 Meet the three LEDs

An LED is a tiny lamp. Your board has three. Each one is joined to a different pin, and in your code you always use the GP number.

LEDColourPin you type in code
LED1🔴 Red11
LED2🟡 Yellow12
LED3🟢 Green13
BZ1🔔 Buzzer — not a light14
Careful — these numbers are new Older worksheets used 14, 13 and 12 for the LEDs. On the LilEx5, GP14 is the buzzer. Type 14 by mistake and you get a beep instead of a light. And old "green = 12" is now yellow, which lights the wrong colour with no error at all.

🤔 Why does the red LED get GP11 and not GP14?

The numbers are not chosen by you — they are decided by whoever designed the board and soldered the copper tracks. On the LilEx5 the designer ran a track from the Pico's GP11 pad to the red LED, GP12 to the yellow one, GP13 to the green one, and GP14 to the buzzer.

Your code has to match the copper. If you tell GP14 to switch on, the electricity goes where GP14's track goes — to the buzzer — no matter what you meant.

This is why every board comes with a pinout sheet. Ours is PINOUT.md. Engineers check it constantly; nobody memorises it.

Board labels are not pin numbers The picture printed on the board uses its own labels, like SW1(11) or SW4(37). Those are positions on the connector. In code you always use the GP number.

🔧 Build the circuit

Wokwi is a free website that pretends to be a real Pico. You build the circuit by dragging parts and drawing wires, then press Play. Nothing can break and nothing can burn out.

1

Start a new project

Go to wokwi.com, click New Project, then choose Raspberry Pi Pico and MicroPython.

2

Find your way around

The screen splits in two: your code (main.py) on one side, your circuit on the other. The Serial Monitor sits underneath — that is where print() messages appear.

3

Add the parts

In the diagram panel, click the blue + button and search for:

LEDpick the red one
Resistorclick it, then set its resistance to 330
4

Draw the wires

Click one pin, then click the pin you want to join it to. A wire appears. Press Esc if you start the wrong one.

Pico GP11 ──[ 330 Ω ]── A (long leg)  🔴  C (short leg) ── Pico GND

The LED's long leg (A) goes through the resistor to GP11. The short leg (C) goes to GND.

⚡ Why the resistor?

On a real board, too much electricity rushes through the LED and burns it out in about a second. The resistor slows the flow down — think of it as a narrow gate in a wide corridor.

Wokwi checks for this too: leave the resistor out and it shows a warning triangle on the LED.

Do this after Wokwi, when you are ready to see it happen for real.

1

Plug in your Pico

Connect the Pico to your computer with the USB cable, and make sure the board's power switch SW5 is on. A small light on the Pico turns on. Nothing else happens yet — that is normal.

2

Open Thonny and find the Pico

Open Thonny. Look at the bottom-right corner of the window and choose MicroPython (Raspberry Pi Pico).

If >>> appears in the Shell at the bottom, Thonny has found your Pico. Well done.

3

Wire the LED

There is nothing to wire. The three LEDs are already joined to pins 11, 12 and 13 inside the LilEx5 board — the same circuit you just built in Wokwi, made permanent in copper.

Three safety rules Never connect a 5V pin to a GP pin — GP pins are 3.3 V only. Never join a power pin to a GND pin. Switch the board off at SW5 before changing any wires.

⌨️ Write the program

In Wokwi, click on main.py. In Thonny, choose File ▸ New. Then type this in exactly. Capital letters matter: Pin is not the same as pin.

from machine import Pin

led = Pin(11, Pin.OUT)
led.on()
print("The LED is on!")
Type it, don't copy it Typing every character yourself is how your fingers and your brain learn the language. Copy-paste teaches you nothing — and you will meet these same lines again in every activity from now on.

🔍 What each line is doing

CodeWhat it means
from machine import PinBorrow the Pin tool out of the Pico's toolbox. Without this line the Pico does not know the word Pin.
led = Pin(11, Pin.OUT)Pick pin 11 and set it to OUT — I want to send power out of this pin. Give it the nickname led.
led.on()Send the power. The LED lights up.
print("The LED is on!")Write a message where you can see it: the Shell in Thonny, or the Serial Monitor in Wokwi.
🏷️ What is led, exactly?

led is a variable — a nickname. It is not a special Python word. You could call it lamp or my_light, as long as you use the same name on every line:

lamp = Pin(11, Pin.OUT)
lamp.on()

This works exactly the same. Try it — it is a good way to prove to yourself that the computer does not "know" what an LED is.

🚀 Exercise — Traffic light check

Now prove you understand the pin numbers.

Task: make the green LED come on instead of the red one, and print a different message.

💡 Hint 1 — I don't know where to start

You only need to change two things in the program you already have. Look at the LED table again, and look at the text inside the print() brackets.

💡 Hint 2 — which number?

Green is LED3, and LED3 is on GP13. So Pin(11, Pin.OUT) becomes Pin(13, Pin.OUT).

✅ Answer — only open this after you have really tried 
from machine import Pin

led = Pin(13, Pin.OUT)
led.on()
print("Green means go!")

📖 Words to remember

GPIOGeneral Purpose Input/Output — a pin you can control from code.
GP numberThe number the Pico knows a pin by. The one you type in code.
OutputA pin set up to send power out.
LEDLight Emitting Diode. A tiny lamp with a long leg (A) and a short leg (C).
ResistorA part that slows the flow of electricity so the LED survives.
VariableA nickname for something, like led.
Shell / Serial MonitorThe window where print() messages appear.

Only the pin number and the message change. Students who rewrite the whole program have missed the point that a variable is a nickname — the rest of the code does not care which pin it points at.

⚠️ Pin numbers changed from the older module

This activity previously used GP14 = red, GP13 = yellow, GP12 = green, which came from a different board. On the LilEx5:

Old moduleLilEx5
Red LED11411
Yellow LED21312
Green LED31213
Buzzer BZ1—14

The failure mode is loud and obvious: a student following an old printout types 14 and the board beeps. Worth demonstrating deliberately once — it makes the “code must match the copper” point better than any explanation.

Note also that old green (12) is now yellow, so a stale worksheet lights the wrong colour with no error message at all. Collect any old printouts.

Teaching notes
  • Don't skip Wokwi. On the LilEx5 the LED wiring is inside the PCB, so students never see a circuit unless they build one. The Wokwi step is where the electronics is actually taught.
  • The most common typo is lowercase pin. MicroPython is case-sensitive; Pin is a class name.
  • led is not a keyword. Renaming it to lamp throughout is a great 30-second demonstration that variables are just nicknames.
  • Students expect led.on() to be temporary. Ask “what would make it stop?” — nothing does, which sets up Activity 2 (loops and sleep).
  • The three safety rules apply from day one: never join 5V to a GP pin, never join a power pin to GND, and switch off at SW5 before changing wires.
